# Frontend architecture (React 19 + TanStack Router/Query + shadcn/ui on Base UI + Tailwind v4)

The SPA must stay **modular**, **portable**, and **boring** — every piece obvious to find, easy to
reuse, easy to delete. This encodes the conventions in `docs/frontend.md`.

## TL;DR

1. **Reusable UI lives in `packages/ui` (`@app/ui`) only.** Never duplicate a shadcn/ui component into `apps/web`.
2. **Build by composition, not duplication.** Check `packages/ui/src/components/ui` and `…/components` first; extend or compose.
3. **`packages/ui` is portable** — no imports from the app, its hooks, or the API client. Props in, callbacks out.
4. **Use design tokens.** Colors/radii/spacing come from CSS vars in `packages/ui/src/styles/globals.css`. Never hardcode hex/`bg-zinc-*`.
5. **Strict types**, named exports, server-validation errors surfaced via `formErrors()`. No raw `axios` in components.
6. **TanStack Query owns all server state — including the session user.** There is no client-state library; add zustand only if genuine cross-component client state appears.
7. **Routes are files under `src/routes/`.** Pages declare intent via `staticData`; the single `_app` guard enforces it.

## Layer map

Organized **by feature**, not by file type.

```
apps/web/src/
├── main.tsx                # createRoot + QueryClientProvider + RouterProvider; 401/419 interceptor
├── router.tsx              # createRouter({ routeTree, context: { queryClient } })
├── routeTree.gen.ts        # GENERATED by @tanstack/router-plugin — never edit
├── routes/                 # file-based routes — thin: staticData + component (+ validateSearch)
│   ├── __root.tsx          #   root layout, notFound → '/', error boundary
│   ├── _app.tsx            #   authenticated shell (DashboardLayout) + THE guard
│   ├── _app/<page>.tsx     #   e.g. users.tsx → '/users'; $id.tsx for params
│   ├── _guest.tsx          #   logged-out-only shell
│   └── _guest/<page>.tsx   #   login, register, forgot-password, reset-password
├── shared/                 # cross-feature primitives (used by 2+ features)
│   ├── lib/                #   http.ts (axios), query-client.ts, query-keys.ts, form.ts, permissions.ts
│   ├── hooks/              #   usePermissions, useServerTable, useAppConfig, useNavItems
│   ├── components/         #   Can, FormField, AppSidebarNav (app-local shared)
│   ├── layouts/            #   AuthLayout, DashboardLayout
│   └── router/types.ts     #   typed `staticData` (AppRouteStaticData) + NavItem
├── features/<feature>/     # one folder per feature, self-contained
│   ├── pages/              #   <Feature>Page.tsx (rendered by a route file)
│   ├── hooks/              #   use<Resource>.ts (TanStack Query)
│   ├── components/         #   feature-only composites
│   └── __tests__/          #   Vitest + React Testing Library specs
├── test/utils.tsx          # renderWithQuery, renderHookWithQuery, createTestQueryClient
└── assets/main.css         # imports @app/ui globals.css

packages/ui/src/            # @app/ui — consumed as source via the @app/ui alias
├── components/ui/          # shadcn/ui primitives, style base-nova on @base-ui/react (CLI writes here)
├── components/data-table/  # DataTable + DataTableSortHeader (@tanstack/react-table v8)
├── components/             # other reusable composites
├── hooks/                  # HEADLESS hooks only (no I/O)
├── lib/utils.ts            # cn()
└── styles/globals.css      # Tailwind v4 entry + design tokens
```

Rules of thumb:
- A file lives in `features/<x>/` if **only** feature `<x>` uses it.
- It moves to `shared/` if **2+** features depend on it (or it's infra like the HTTP client).
- Route files are wiring only — the page component lives in `features/<x>/pages/`.
- Tests live next to the code they cover (`__tests__/`).

## "Where does this go?" decision tree

```
Is it an entire URL/screen?
├── Yes → route file src/routes/_app/<path>.tsx  +  page features/<feature>/pages/<Feature>Page.tsx
└── No → continue ↓
Could another app/feature reuse this exact piece?
├── Yes, a primitive (button-like) → `pnpm --filter @app/ui ui:add <name>` (lands in packages/ui/src/components/ui)
├── Yes, a composite (StatCard, EmptyState, PageHeader) → packages/ui/src/components/<name>.tsx
└── No, only this app's domain → continue ↓
Used by exactly one feature?
├── Yes → apps/web/src/features/<feature>/components/<Name>.tsx
└── No, 2+ features → apps/web/src/shared/components/<Name>.tsx
```

## Reuse-first workflow (mandatory)

Before creating a component:
1. `ls packages/ui/src/components/ui/` — does a shadcn primitive already exist? **Read its file** — the Base UI flavour differs from Radix docs.
2. `ls packages/ui/src/components/` — does a composite exist (e.g. `data-table`)?
3. If shadcn ships it: `pnpm --filter @app/ui ui:add <component>` (uses `packages/ui/components.json`).
4. Only then build new. Place it in `packages/ui/src/components/` if reusable, `apps/web/src/...` if app-specific.

## Component conventions

```tsx
import type { ReactNode } from 'react'                         // 1. type imports / react
import { Button } from '@app/ui/components/ui/button'          // 2. @app/* (workspace shared)
import { cn } from '@app/ui/lib/utils'
import { usePermissions } from '@/shared/hooks/usePermissions' // 3. @/* (this app)

export function PageHeader({ title, actions, className }: {
  title: string
  actions?: ReactNode
  className?: string
}) {
  return <header className={cn('flex items-center justify-between', className)}>…</header>
}
```

- Function components, **named exports** (no default exports), PascalCase file names.
- Props typed inline or via an interface; callbacks are `onX` props (`onOpenChange`, `onSubmit`).
- Accept `className` and merge with `cn()`.
- Keep components under ~250 lines; one responsibility each.

### Base UI shadcn specifics

- No `asChild` — use the `render` prop: `<DropdownMenuTrigger render={<Button variant="ghost" />}>`.
  A `Button` rendering a non-button needs `nativeButton={false}`: `<Button render={<Link to="/" />} nativeButton={false}>`.
- `DropdownMenuItem` uses `onClick` (no `onSelect`); `DropdownMenuLabel` must sit inside a `DropdownMenuGroup`.
- `Checkbox`/`Switch`: `checked` + `onCheckedChange`; `Select`/`Tabs`: `value` + `onValueChange`.
- `DialogContent`/`AlertDialogContent` unmount while closed — put the stateful body (mutations, form
  state) in an inner component rendered inside the content so each open starts fresh (see `UserFormDialog`).

### Import sources

| Source | Use |
|---|---|
| `@app/ui/components/ui/<x>` | shadcn/ui primitives |
| `@app/ui/components/data-table` | `DataTable`, `DataTableSortHeader`, `ColumnDef` |
| `@app/ui/hooks/<x>` | headless hooks |
| `@app/ui/lib/utils` | `cn` |
| `@app/types` | shared API contract types |
| `@/features/<f>/...` | feature-local |
| `@/shared/...` | cross-feature, app-local |
| `lucide-react` | icons |

**Never** import `@/` paths inside `packages/ui/*` (breaks portability — verify with
`grep -rn "from '@/" packages/ui/src/`, should be empty).

## State management

| Use case | Tool | Where |
|---|---|---|
| Local UI state | `useState` / `useReducer` | in the component |
| Headless reusable logic (no I/O) | hook | `packages/ui/src/hooks/` |
| **Server data** (fetched) | **TanStack Query** `useQuery` | `features/<f>/hooks/use<Resource>.ts` |
| **Writes** | **TanStack Query** `useMutation` | same file |
| **Session user** | `userQueryOptions` (`authKeys.user()`) | `features/auth/hooks/useAuth.ts` → `useUser()` |
| URL state (filters, redirect, tokens) | route `validateSearch` (Valibot) | route file |

- **Axios:** one instance at `src/shared/lib/http.ts` (`withCredentials`, CSRF, `Accept: application/json`). Import as `http`; never raw `axios` in a component. See `sanctum-fortify-auth`.
- **Query keys:** all in `src/shared/lib/query-keys.ts`. Never inline strings.
- **Current user:** `useUser()` (`User | null`); refresh after a self-mutation with `useRefreshUser()`.
- **Permissions:** `usePermissions().can('x')` or `<Can permission="x">…</Can>`. To disable instead of hide, pass `disabled={!can('x')}`.

## Forms

- Labelled controls use `<FormField label htmlFor error hint>` — don't hand-roll Label + error `<p>`.
- Server 422s: `const errors = formErrors(mutation.error)` → `errors.fields.<name>` per field
  (also `aria-invalid={!!errors.fields.x || undefined}`), `errors.alert` in an `<Alert variant="destructive">`.
- Simple forms may be uncontrolled + `formValues(event.currentTarget)`; forms with pre-fill, checkboxes
  or derived UI use `useState` (see `features/users/components/UserForm.tsx`).

## Tables

`const { data, tableProps } = useServerTable<T>({ resource, endpoint })` (or the feature's wrapper,
e.g. `useUsersTable()`) → `<DataTable columns={columns} data={data} {...tableProps} toolbar={…} />`.
Columns go in `useMemo`; sortable headers use `<DataTableSortHeader column={column} label="Name" />`.
`useServerTable` is the only place that defines the `page`/`per_page`/`sort`/`dir`/`q` contract.

## Styling

- Tailwind v4 utilities only. Tokens via CSS vars (`bg-primary`, `text-muted-foreground`, `border-border`) — never `#fff`/`bg-zinc-700`.
- Merge consumer `className` with `cn()`. Dark mode via `.dark` on a parent (`@custom-variant dark`).
- No `dangerouslySetInnerHTML` on user input.

## Routing

- One file per route under `src/routes/`; the router plugin generates `routeTree.gen.ts` and code-splits each route.
- Authenticated pages go under `src/routes/_app/`. A route declares
  `staticData: { permission?, module?, nav?: { title, icon, order } }` + `component` — **never** its own
  `beforeLoad` for auth/permission; `routes/_app.tsx` reads `staticData` from every matched route.
- The sidebar is derived from routes that set `staticData.nav` (`useNavItems`), filtered by permission and module.
- Search params are validated with Valibot in `validateSearch` (e.g. `/login?redirect`, `/reset-password?token&email`).
- Navigate with `<Link to="/users">` / `useNavigate()`; path params via `$id.tsx` + `Route.useParams()`, passed to the page as props.

## Anti-patterns (refuse to write)

- A second `Button` in `apps/web` (there's exactly one, in `@app/ui`).
- A shadcn primitive copied into `apps/web` (the CLI writes to `packages/ui`).
- `axios.get(...)`/`fetch(...)` inside a component (use a Query hook).
- Server data copied into component/global state, or a client store for the session user.
- Per-route `beforeLoad` auth/permission checks; hand-maintained nav lists.
- Inline query-key strings; hardcoded API URLs.
- One feature importing another feature's internals (extract to `@/shared/` or `@app/ui`).
- `@/...` imports inside `packages/ui`.
